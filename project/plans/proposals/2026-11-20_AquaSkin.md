# Design Proposal: Aqua (Mac OS X 10.0) skin

**Status:** Proposed, 2026-11-20. No code written.
**Branch:** `feature/skins-model` (follows System 7, Platinum, OPENSTEP).
**Master Plan Reference:** Skins theme the whole OS (`project_skins_whole_os`); the skins spike (`2026-11-17_SkinsSpike.md`) listed Aqua as the third look after the Macintosh and NeXT ones.
**Companion:** `2026-11-20_LiquidGlassSkin.md` (shares the translucency work in Phase 3).

## 1. Objective

Ship `Theme.aqua`: the Mac OS X 10.0 "Cheetah" look as a theme, covering the same surface list the other skins cover (buttons, default button, fields, window and title bar with its three lights, scroll bars, menus and menu bar, dock, selection, icons), in the light appearance only, with every number either measured against the references or labelled as chosen.

## 2. Motivation

Aqua is the first skin whose depth is made of **light** rather than bevel steps. System 7, Platinum and OPENSTEP are stacks of 1 to 3 px edge steps over flat fills; Aqua is a gel of two gradient bands with a hard step, a gloss highlight, a tinted rim and a soft shadow, on a pinstriped ground, with translucent menus and a pulsing default button. It stresses the parts of the surface model that the Macintosh and NeXT skins never touched.

**Current situation.** The model already holds much of what Aqua needs, because the spike anticipated it: `GradientSpec` allows equal stop positions (the hard step), `CornerRadius.capsule`, `SurfaceRecipe.backdropBlur`, `PatternSpec` up to 16 x 16 (the 1 x 4 pinstripe), `ShadowLayer` with inset and spread, `ScalePolicy.free`, and `ColourReference(source:opacity:)`. `WindowControl` already names Aqua's three lights in its docs.

**Gaps** (section 4 lists the fixes):
1. A gradient painted into an **inset rectangle** (the gloss highlight sits inside the button, not on its full box). Today every layer covers the whole box.
2. A **repeating or sized gradient** and a pattern that does not pixelate (pinstripe at fractional scale is fine as a 1 x 4 pattern; the gel is not).
3. **Round window controls** (the traffic lights are 12 px discs with their own gel); `WindowControls` and the title-bar recipes assume square boxes.
4. **Animation**: the default button pulses. Nothing in the model is time-varying.
5. **Dock** is a scale-and-magnify strip rather than NeXT's tile column; `dockTile`/`dockLabel` do not describe it.
6. **Scroll bar** as capsule thumb with a gel, a recessed grooved track and paired arrows at the end (10.0 default) rather than the Macintosh or NeXT arrow tiles.

**Workaround today:** none; Aqua is the one reference with captures and no theme.

## 4. Proposed architecture and API additions

**New files**
- `Sources/DesignTokens/Themes/ThemeAqua.swift` (recipes, palette, metrics), mirroring `ThemePlatinum.swift`.
- `Generated/` goldens regenerated by `swift run design-tokens Generated` (an `aqua.*` set).
- `Tests/DesignTokensTests/AquaTests.swift`.

**Modified files**
- `Theme/Surface.swift` (layer extensions below), `Emitters/ThemeCSSEmitter.swift` (new properties), `Emitters/GTKEmitter.swift` (drops what it cannot draw and says so in the ledger), `Theme/WindowControls.swift`, `Theme/Menu.swift`, `Theme/Dock.swift`, `Theme/Theme.swift` (registry), docs and CHANGELOG.

Every addition is optional and absent from the JSON of themes that do not use it (the strict canonical `ThemeCodec` with `decodeIfPresent`/`encodeIfPresent`), so the existing goldens do not change.

### 4.1 Layer inset: the gloss highlight

```swift
public enum SurfaceLayer {
    // existing cases ...
    /// A gradient painted into a rectangle inside the box (Aqua's gloss: top half, inset 1 px at the sides, to a radius smaller than the box's).
    case inset(Insets, radius: CornerRadius?, SurfaceLayerPaint)
}
public indirect enum SurfaceLayerPaint { case fill(ColourReference), gradient(GradientSpec) }   // no nesting of insets
```

CSS: an extra `background-image` cannot be clipped to an inset rectangle, so the emitter writes the gloss as a `::before` pseudo-element on the component (`position:absolute; inset:…; border-radius:…; background:linear-gradient(…); pointer-events:none`). This needs `position: relative` on the component and `overflow: hidden` is **not** used (it would clip the drop shadow). **Alternative considered:** `background-origin`/`background-size` on a second `background` layer, which needs no pseudo-element and keeps components untouched. This is preferred where it expresses the layer: `background: linear-gradient(...) 1px 1px / calc(100% - 2px) 50% no-repeat`. The radius of an inset layer cannot be set that way, so a rounded gloss uses the pseudo-element. Decision in section 12.

### 4.2 Sized gradients and non-pixelated patterns

`PatternSpec` sets `image-rendering: pixelated`, right for System 7 and wrong for Aqua at 1.5x. Add `PatternSpec.smooth: Bool` (default false, omitted from JSON) so the pinstripe is drawn with the default sampler; at `ScalePolicy.free` the 4 px period becomes 4 CSS px at any zoom, which is the original's behaviour at 1x and what OS X did at its own pixel doubling later.

### 4.3 Round window controls

```swift
public struct TitleBarMetrics { /* existing */
    public var controlShape: ControlShape?     // .square (default) | .circle
}
public enum ControlShape: String, Sendable, Hashable, Codable { case square, circle }
```

With `.circle` the box recipes (`windowBox`, `windowBoxZoom`, `windowBoxMinimize`) use `CornerRadius.capsule` on a square box, which the emitter already writes. The three lights differ by colour only, so the recipes are three gradients; the glyphs shown on hover (x, minus, plus) are ink drawn on the `hover` state of the same roles. The lights have **no per-window inactive grey in 10.0 beyond flattening to grey**: handled by `.disabled` as for Platinum.

### 4.4 Pulse

Smallest honest model: a recipe-level optional, not a new animation system.

```swift
public struct PulseSpec: Sendable, Hashable, Codable {
    public var from: Int        // index into the recipe's layers whose gradient is swapped
    public var period: Double   // seconds
    public var alternate: GradientSpec
}
public struct SurfaceRecipe { public var pulse: PulseSpec? }   // optional, absent from JSON when nil
```

Emitted as `@keyframes dt-pulse-<role>` toggling `background-image` between the two gradients, wrapped in `@media (prefers-reduced-motion: no-preference)`, and `animation: … infinite`. Reduced motion leaves the static blue gel. Non-web targets ignore it and note it in the ledger. Only `buttonDefault.rest` uses it.

### 4.5 Translucent menus

Aqua 10.0 menus are translucent (the desktop shows through slightly) without blur; blur arrives in later releases. This is **expressible already** with `ColourReference(opacity:)` on the fill and `backdropBlur: nil`. Phase 0 measures the opacity against two known backdrops (the capture has one; two are needed for a fit, as for Liquid Glass), and if only one exists the value is labelled chosen. The CSS floor is unaffected (no `backdrop-filter` is required).

### 4.6 Scroll bar

Uses the existing `ScrollBarMetrics` and roles. Aqua's pieces: `scrollTrack` a recessed groove (inset shadows, a vertical-then-horizontal gradient), `scrollThumb` the blue gel capsule (`CornerRadius.capsule`, the same gel as the default button, transposed for vertical via `recipe.transposed`), `scrollArrowStart`/`End` small gel squares, with a new optional `ScrollBarMetrics.arrowPlacement` (`.split` default, `.together` for 10.0's both-arrows-at-one-end). One enum field, absent when `.split`.

### 4.7 Dock

The dock is a shelf plus icons that scale on hover. The model has `dockTile` and `dockLabel` for NeXT's tile column. Add one role `dockShelf` (a translucent rounded bar) and keep tiles as plain icons with an optional `DockMetrics.magnification: Double?` (documented, emitted as a CSS `transform: scale()` on `:hover` with a transition under `prefers-reduced-motion: no-preference`). Genie and Exposé effects are **out of scope**: these are window-manager animations, not surface recipes, and the theme model has no window lifecycle.

### 4.8 Palette, fonts, icons

- Palette: `ThemePalette` with the measured greys, the blue gel stops, the selection blue, the pinstripe greys named `pinstripeLight`/`pinstripeWhite`/`pinstripeDark` (`ThemePalette` extras, as Platinum's `navy`).
- **Fonts.** Lucida Grande first, then honest fallbacks: `"Lucida Grande", "Lucida Sans Unicode", "Lucida Sans", system-ui, sans-serif`. Nothing is bundled (the standing rule: original face first, honest fallbacks, the ledger says when the original is missing). Monospace: Monaco, then `ui-monospace`, as the other Macintosh skins.
- **Icons.** Original artwork only (the standing rule): Aqua's glossy icons are Apple artwork and are not reproduced. The icon set follows the OPENSTEP approach: our own SVGs drawn in the Aqua manner (gel, soft shadow, reflection), close look-alikes at 128 px and scaled down, not copies. Which icons ship is open question 4. Local pixel traces never go in the repo or `Generated/`.

## 6. Error handling

Same as the other skins: recipes are literals built with the internal `init(literal:)` forms; public initialisers validate and throw the existing `SurfaceError` cases (stop order, cell size). New: `PulseSpec` throws `SurfaceError.pulse` for a non-finite or non-positive period or an out-of-range layer index; an inset layer throws on negative insets. Decoding applies the same checks. Unknown JSON keys already reject under the strict canonical codec.

## 7. Browser floor

Unchanged: Chrome 111 / Edge 111 / Safari 16.2 / Firefox 113. Everything in this proposal is inside it: multiple backgrounds with size and origin, `border-radius: 9999px`, `box-shadow` inset and spread, `::before`, `@keyframes`, `prefers-reduced-motion`, `backdrop-filter` (Safari prefixed form is already emitted), `inset:` shorthand (Chrome 87, Safari 14.1, Firefox 66). No new feature needs a version bump; Phase 1 adds a test that scans the emitted Aqua CSS for properties outside the floor list, the same test as the other skins.

## 8. Testing strategy (strict TDD, red then green, commit at each green)

- **Model:** init validation (`PulseSpec`, inset layers), codable round trip, absent-field JSON for existing themes (the old goldens are byte-identical: the guarding test).
- **Measured tiles:** expected tiles are built from the measured description as for Platinum (`tile(_:_:_:)` helper), not from the recipe, and compared with the headless-Chrome render: the harness in the scratchpad `pm/` renders the emitted CSS at 1x and a PIL run compares rows against the capture's runs (the vertical gel runs above are the assertion: a hard step at the midpoint, outline colours, shadow rows).
- **CSS contract:** class and selector tests for each new rule, ordering tests (pulse inside the reduced-motion query; the gloss pseudo-element before states), a negative test that System 7, Platinum, OPENSTEP and Swiss emit none of the new properties.
- **Goldens:** `Generated/` compared with a fresh emit.
- **Auditors:** no `split(separator:"\n")`, no weak assertions, no exact Double `==`, no double-backtick DocC links to private members. Gate 0 errors, 0 warnings, no suppressions.

## 9. Performance

Gradient layers and pseudo-elements are cheap. The pulse is a `background-image` swap, which repaints the button only; kept off by reduced motion. Backdrop blur is not used by 10.0 menus. The pinstripe is a 1 x 4 tile. Theme CSS grows by an estimated 3 to 4 KB over Platinum's.

## 11. Constraints & compliance

- No force unwraps, `try!` or casts; guards and early returns; Swift 6 strict concurrency; all public API documented in DocC (no double-backtick links to private members).
- No fonts bundled. No Apple artwork: icons and wallpaper are original. No pixel traces in the repo.
- **Trademark and design right.** "Aqua" and the Mac OS X look are Apple's; the earlier spike marked this open (Q4). The theme is a look-alike measured from public captures, identified in the UI as "Aqua (Mac OS X 10.0 look)" and not as Apple software, and ships no Apple assets. Whether the name is acceptable is open question 5.

## 12. Alternatives considered

1. **Gloss as a second `background` layer with `background-size`** (no pseudo-element). Simpler CSS and no `position: relative`; cannot round the gloss separately. Recommended when the inset gloss is square at the sides (measure first), pseudo-element otherwise. Phase 0 decides from the captures.
2. **Image sprites** for the gel (what the original did). Rejected: not themeable, not resolution independent, and artwork-adjacent.
3. **A general animation model** (`Animation` keyframes per recipe). Rejected for now: one consumer (the default button) does not justify it; `PulseSpec` can be generalised later without a break because it is optional.
4. **SVG filters for the gloss and lighting.** Rejected: harder to scale, no gain over gradients at this fidelity.
5. **Model the dock as a window-manager feature.** Rejected: only its look (shelf and tile scale) is in scope.

## 13. Adversarial review

- *Pressed, disabled and focus are assumed.* True; labelled chosen in the doc comment and the ledger, as OPENSTEP's were. The risk is a wrong look in states, not a wrong rest state.
- *Capture was a downscaled screenshot.* If anti-aliasing or scaling touched the runs, step positions drift by a pixel; the hard step is read from several buttons to avoid reading one artefact.
- *The pulse makes golden files time-varying.* It does not: the CSS is static; only the browser animates.
- *The gloss pseudo-element breaks components that already use `::before`.* Phase 1 greps the components CSS for `::before`/`::after` use and picks the safe route or the layered background.
- *Translucent menus over arbitrary content lose contrast.* Ink is checked against the worst-case backdrops in the conformance ledger, as Liquid Glass will be.
- *Aqua evolved* (10.0 to 10.9 differ). This is explicitly **10.0**; later Aquas are separate themes.

## 14. Future directions

Later Aqua releases (brushed metal, 10.3 onward, the blur menus of 10.5+ and the flat 10.10), a dark pinstripe (not part of the original, so never claimed), SwiftUI rendering of the same recipes, and the live re-measure if a 10.0 oracle appears.

## 15. Documentation strategy

DocC comments with the measurement provenance on every recipe (as `ThemePlatinum.swift`), `SkinMeasurements.md` sections per Phase 0 and per theme phase, CHANGELOG entries under "Added (skins)", README status line, and the release doc housekeeping (`project/master_plan.md`, CHANGELOG link references, Last Updated).

## 16. Open questions

1. **Gloss method:** pseudo-element (rounded, exact) or layered `background` (no markup change, square only)? Recommendation: decide from Phase 0 captures; default to the layered background.
2. **Pressed, disabled and focus** without a live oracle: ship chosen values labelled as such, or hold the skin until a 10.0 emulator is found?
3. **Pulse:** accept the optional `PulseSpec` on `SurfaceRecipe`, or leave the default button static in v1 and add motion later?
4. **Icons:** how many original Aqua-style icons for v1 (the OPENSTEP set size, or only folder, document, app and trash)?
5. **Name and trademark:** ship as "Aqua (Mac OS X 10.0)" in the registry and UI, or under a neutral name ("Gel") with the Aqua description in the docs?

## Decisions, 2026-11-25 (owner)

Hold: **no Aqua work starts until the skins gallery (`2026-11-25_SkinsGallery.md`) has been reviewed.**

1. **Gloss highlight: a pseudo-element** (rounded, exact), not a layered background.
2. **Pressed, disabled and focus states: ship**, and take them from a later release rather than choosing them: Infinite Mac lists Mac OS X 10.1, 10.2 (Jaguar), 10.3 (Panther) and 10.4 (Tiger) (checked 2026-11-25; 10.2 and 10.4 carry its "Unstable" tag, 10.3 and 10.1 do not). **Use 10.3 as the live oracle for states.** It is not 10.0: where 10.3 differs from the 10.0 captures, the skin follows 10.0 for geometry and uses 10.3 only for the states 10.0 cannot show, and the difference is recorded in `SkinMeasurements.md`. Whether the held-mouse method that worked for Mac OS 8.0 works on 10.x is not known and is the first thing to try.
3. **Default-button pulse: yes, an optional `PulseSpec` now.**
4. **Icons: as many as possible** (original artwork only), prioritised by the Finder and Dock set; scope is set in the checklist.
5. **Registry name: "Water"** (id `water`), not "Aqua", given the trademark question. Code comments may say the look is the Mac OS X 10.0 era; the registered name and id do not.
