# Design Proposal: how an app adopts the tokens with its own palette (0.8.0)

Status: proposed 2026-11-10, branch `feature/app-palette-0.8.0` from 0.7.0. Owner: jpurnell.

## 1. Objective

`AppPalette` and `Theme.composed(with:)` exist (0.5.0, Princeton is the worked example). What is missing is the
act of adopting: an app (WineTaster, FleetWatch, KEXPPower, narbis, HockeySimApp) keeps its own accent and series on
Swiss's structure, and must be able to (1) declare that palette in **one file**, (2) have it **validated** against
Swiss in light, dark and increased contrast, with a **ledger** of exact findings instead of suppressions, (3) assert
that from its own test target, and (4) be **recognised** by the drift checker (quality-gate-swift, in progress in
another session) so that file, and only that file, may hold colour literals.

## 2. Contract summary (read this if you are the checker agent)

### 2.1 The marker: protocol conformance `AppPaletteSource`

```swift
import DesignTokens

// the one file in the app that may contain colour literals
enum WinePalette: AppPaletteSource {
    static let palette = AppPalette(id: "winetaster", accent: ..., series: [...], ...)
}
```

`AppPaletteSource` is a public protocol in module `DesignTokens`:

```swift
public protocol AppPaletteSource: Sendable { static var palette: AppPalette { get } }
```

A Swift file **is a declared app-palette file** iff a SwiftSyntax walk finds a `struct`, `enum`, `final class`,
`actor` or `extension` declaration (top level or nested) whose **inheritance clause names `AppPaletteSource`**
(also `DesignTokens.AppPaletteSource`). Why this and not a comment:

- the compiler enforces it: a type that claims the marker must provide `palette`, so the marker cannot be a lie that
  compiles; a comment can be pasted on any file to buy an exemption;
- it is visible to a syntactic checker with no type resolution, and the same file is what the app's test target calls
  `WinePalette.validate()` on, so the exemption and the validation are the same declaration.

**Required shape for the exemption to apply** (the checker should enforce these, and report a finding otherwise):

1. the file contains exactly one call `AppPalette(` whose first argument is `id:` with a **string literal**; that
   literal is the palette id (used in messages; it must be unique across the repository);
2. exactly one declaration in the file conforms to `AppPaletteSource`;
3. recommended, optional: some file under a test target mentions that declaration's name together with `validate(`
   and `isConformant` (an exempt file nobody tests is the hole this feature exists to close). A checker that cannot
   find one may emit a warning, not an error.

**What the exemption covers:** colour-literal rules only (`Color(red:green:blue:)`, `Color(hex:)`, `NSColor`/`UIColor`
component initialisers, `0xRRGGBB` and `"#RRGGBB"` literals, `RGB(rgb:)`, `ColorValue(`). Everything else
(fonts, radii, rule weights, spacing) still applies in the file. The exemption is per file, never per directory, and
never by comment.

**Non-Swift output.** An app that emits web or terminal files from its palette gets generated files whose first line
is `/* Generated by design-tokens. ... Theme: swiss+<id> ... */` (CSS) or the equivalent header (JSON, ANSI): the
theme id is `<theme>+<palette id>`. A checker may treat a generated file whose header names `swiss+<id>` (any theme
id ending `+<id>` for a declared `<id>`) as declared. The files are generated, not hand-edited.

**Comment convention.** `// design-tokens: app-palette <id>` is *not* a marker the checker should honour. It may
appear as documentation; it grants nothing.

### 2.2 What "validated" means (what the exemption trades for)

`WinePalette.validate()` (protocol extension; also `palette.validate(on:)`) returns an `AppPaletteConformance`. It
composes the palette onto Swiss (or another theme) and measures: series lightness band, chroma, colour-vision and
normal separation, mark contrast against background and card surface, accent and on-accent contrast, supplied
ramps, in light, dark (when the palette has dark values) and each increased-contrast appearance for which a series
has a value. The palette declares its own **ledger** (`conformance:`), exactly like the built-in themes: every
finding must be listed with its measured value and threshold, a finding that is not listed, a listed value that has
changed, and a listed finding that no longer occurs are each a **deviation**, and `isConformant` is
`deviations.isEmpty`. Nothing is suppressed.

## 3. API

All additive; every new field defaults to the old behaviour; JSON written by 0.7.0 still decodes.

### 3.1 `AppPalette` gains three fields

| Field | Type | Meaning |
|---|---|---|
| `maxSeriesPerChart` | `Int?` | the most series one chart may plot (WineTaster: 5). Not a palette size: WineTaster has more wine types than that. `nil` means the method's 8. |
| `labelTogether` | `[SeriesPair]` | pairs that must be labelled directly wherever a chart plots both, by the app's own rule, whether or not the colours fail a threshold (WineTaster: Light White + Full White). Unlike `SeriesOrder.labelRequired`, which records *measured* failures and is checked for staleness, this is a declared rule and is never stale. |
| `conformance` | `Conformance` | the ledger, `.strict` by default. |

Palette-level structural checks (findings, check `.structure`): `maxSeriesPerChart < 1`; a `labelTogether` pair
naming a series the palette does not have; a duplicate series name; more series than the method's 8 (existing
`.seriesCount`). The existing `ThemeValidator.validate(_:on:)` gains ramp findings for a **supplied** ramp
(`sequential`, `diverging`); a palette that supplies none is measured exactly as before.

### 3.2 `AppPaletteConformance`

```swift
public struct AppPaletteConformance: Sendable, Equatable {
    public let paletteID: String; public let themeID: String
    public let appearances: [ValidationAppearance]   // the ones measured
    public let findings: [Finding]                   // every measurement that falls short
    public let deviations: [String]                  // findings vs. the declared ledger
    public let labelRequirements: [LabelRequirement] // pair + why (measured, declared, both)
    public var isConformant: Bool                    // deviations.isEmpty
    public var report: String                        // exact, multi-line, printable
    public var ledgerSource: String                  // the measured findings as Swift source, to paste into `conformance:`
}
```

Entry points: `AppPalette.validate(on: Theme = .swiss) -> AppPaletteConformance` and, on the protocol,
`static func validate(on:)`. `report` lists, in order: the verdict, each deviation, then every finding as
`severity check | appearance | subject: measured vs threshold`, then the label requirements. It is what
`#expect(WinePalette.validate().isConformant, "\(WinePalette.validate().report)")` prints on failure.
`ledgerSource` is the bootstrap path: write the palette with `.strict`, run, paste the measured ledger, and review
each line as a decision (this is how Swiss's and Princeton's ledgers were made).

### 3.3 Chart rule check

`AppPalette.chartViolations(plotting: [String], labelled: Set<String> = []) -> [ChartRuleViolation]` for chart
adapters and tests: more than `maxSeriesPerChart` series; a name that is not in the palette; a `labelTogether` or
measured-required pair both plotted with either member not in `labelled`. Pure; it measures nothing.

### 3.4 Public builders

`Adaptive(light: UInt32, dark: UInt32? = nil, ...)`, `NamedAdaptive(_ name:, light:, dark:)` and
`Ramp(light: [UInt32], dark: [UInt32]? = nil)` so a palette file reads as its colours and not as `ColorValue(RGB(`
plumbing. Packed `0xRRGGBB`.

### 3.5 Web and terminal output (cheap, only the wiring)

`AppPalette.theme(on: Theme = .swiss) -> Theme` (the composition, ids `swiss+<id>`) plus the existing
`ThemeCSSEmitter`, `ThemeJSONEmitter`, `ANSIEmitter` work on it unchanged; tests pin that the app's accent and
series appear and Swiss's surfaces are kept. No new emitter, no new generated file in this package (an app's
files are the app's output).

## 4. Worked example (tests and docs only)

`WineTasterShapedPalette` in the test target, **not shipped as WineTaster's**: accent `#7F0017`, wine-type series,
`maxSeriesPerChart: 5`, `labelTogether: [light white, full white]`, entity order, with a ledger measured in the
tests' own derivation (expected values from closed-form WCAG contrast of the stated hex values, not read back from
the validator). The docs page `project/docs/technical/HowAnAppAdoptsTheTokens.md` walks the same example.

## 5. Tests (red first, cannot pass vacuously)

- a strict palette with a known failing mark (a yellow, 1.07-ish contrast computed by hand from the WCAG formula)
  is **not** conformant; the same palette with its exact ledger is; with one value off by 0.01, one removed, one
  extra: each a distinct deviation message;
- `isConformant` for a clean palette is true and `findings` is empty (a palette whose measured set is empty must not
  be vacuous: the test also asserts the appearances measured are `[.light, .dark]`);
- a palette with dark values is measured in light and dark; one with `lightIncreased` also in `.lightIncreased`;
- `maxSeriesPerChart`, `labelTogether`, duplicate and unknown names, supplied ramp findings;
- `chartViolations` per rule, and that labelling both members clears it;
- codec: 0.7.0-shaped JSON (no new keys) decodes with defaults; the new fields round-trip;
- marker: a fixture Swift source in the tests is scanned with the documented rule (string-level, as the contract
  is syntactic) to pin the contract text's examples compile-shaped; the protocol's `palette` is what `validate()` reads;
- emitters: CSS/JSON/ANSI of `palette.theme()` contain the app accent and the theme id `swiss+<id>`.

## 6. Not doing

- no WineTaster (or any app) colours in this package; apps are not edited from here;
- no automatic ledger update; no suppression of any kind;
- no dark values are invented for a palette that has none: it is measured light-only, as `composed(with:)` already
  decides;
- the checker itself (quality-gate-swift) is another agent's.

## 7. Open questions

1. Should an app be *required* to ledger, or may a `.strict` palette that happens to be clean stay `.strict`? (Plan: the latter; strict is a ledger of zero.)
2. `AppPaletteSource` is `Sendable`, so conforming types are Sendable by default; confirm the apps' strict-concurrency settings are compatible.
